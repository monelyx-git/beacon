# Beacon i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Beacon site can publish its docs in several languages: `content/` is the default language, `content/<code>/` mirrors it for each other language.

**Architecture:** `scanContent` already gives `content/es/x.md` the slug `es/x`, so routes exist for free. A new pure module `src/cli/locales.js` groups pages by locale, builds one nav per locale and answers counterpart, switcher, `hreflang` and missing-translation questions. `site.js` exposes the result through the virtual module; the layout renders `lang`, the locale's nav, a language switcher and alternates. Chrome strings come from one plain dictionary.

**Tech Stack:** Node >= 22.2 ESM (`.js`, no TypeScript), Astro 7, Preact, Pagefind, `node --test`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-07-i18n-design.md`

## Global Constraints

- Everything in English: code, comments, identifiers, logs, errors, UI copy, tests, commits. (The only non-English text is the Spanish dictionary.)
- No new dependencies. If one seems needed, stop and raise it (needs an ADR).
- One commit per task, Conventional Commits. No `Co-Authored-By` or other attribution trailers (AGENTS.md rule 10).
- With `locales` unset the generated HTML is byte-identical to today. Existing tests must pass untouched; a failing one is a regression to fix in the code, never a test to loosen.
- A missing translation is a warning, never a build error.
- Budgets from the main design must hold (`scripts/measure-budget.mjs`).
- Config format: `"locales": ["en", "es"]`, lowercase codes (`en`, `es`, `pt-br`), first is the default; absent means `["en"]` with today's behavior.

## Review Focus

Each line is pinned by a test in the task named in brackets.

1. A `content/es/` page with no default-language counterpart: the switcher sends that page to the default home, nothing crashes. [Task 2]
2. A configured locale with no pages: build error naming the code. [Task 2]
3. `locales: ["es"]`: `<html lang="es">`, Spanish chrome strings, no switcher, no URL prefix. [Task 5]
4. A hyphenated code (`pt-br`): validation accepts it, `content/pt-br/` becomes that locale, chrome strings fall back to English. Uppercase or duplicate codes are rejected. [Tasks 2, 3, 4]
5. A Spanish page linking to a sibling `.md` resolves to the `/es/` page; one linking to a file that exists only in the default language resolves to that page. [Task 5]

### Task 2: `locales.js`: parsing, grouping, nav and lookups

**Files:**
- Create: `src/cli/locales.js`, `test/locales.test.js`
- Modify: `src/cli/content.js` (`rootRedirect` gains a `home` parameter)

**Interfaces:**
- Consumes: `Page` (`{slug, file, title, description?, order?}`) and `buildNav(pages): NavNode[]` from `src/cli/content.js`.
- Produces (all exported from `src/cli/locales.js`; `LocPage = Page & {locale: string, rel: string}` where `rel` is the slug without the locale prefix):
  - `parseLocales(raw: unknown): string[]`. Throws `beacon.config: "locales" ...` for a non-array, empty array, a code not matching `/^[a-z]{2,3}(-[a-z0-9]{2,8})?$/`, or duplicates.
  - `prefix(code: string, locales: string[]): string`. `''` for the default (`locales[0]`), else `/<code>`.
  - `homeHref(code: string, locales: string[]): string`. `/` or `/<code>/`.
  - `assignLocales(pages: Page[], locales?: string[]): LocPage[]`. With `locales` undefined every page is `{locale: 'en', rel: slug}`. Otherwise a page belongs to the non-default locale whose code equals its first slug segment; all others are default. Throws if a page's first segment is the default code (message tells the author to move `content/<code>/` up one level), and if any configured locale ends with zero pages (message names the code).
  - `navFor(pages: LocPage[], code: string, locales: string[]): NavNode[]`. Runs `buildNav` on that locale's pages with `slug` replaced by `rel`, then prefixes every `href` with `prefix(code, locales)` (the root `/` becomes `/es/`). Own pages and own `order` only.
  - `counterpart(pages: LocPage[], page: LocPage, code: string): LocPage | undefined`. Same `rel`, other locale. File path only, frontmatter never matters.
  - `switcherLinks(pages, page, locales): {code: string, href: string, current: boolean}[]`. One entry per locale; `href` is the counterpart's page path if it exists, else `homeHref(code, locales)`. A `page` without `rel` (the 404 page) gets homes only.
  - `alternates(pages, page, locales): {hreflang: string, href: string}[]`. Empty when the page has no translation; otherwise one entry per available version plus `{hreflang: 'x-default', href: <default version>}` when the default version exists. Relative paths (layout prepends `config.site`).
  - `missingTranslations(pages, locales): Record<string, string[]>`. For each non-default locale, the default-language `rel` values lacking a counterpart (empty arrays omitted).
- Modify `rootRedirect(nav, home = '/')`: returns null when the first target equals `home`.

- [ ] **Step 1: Write failing tests in `test/locales.test.js`** (build `LocPage`s with `assignLocales` over hand-made `Page` objects, no filesystem): `parseLocales` accepts `['en','es','pt-br']`, rejects `[]`, `'en'`, `['EN']`, `['en','en']`, `['english']`; `assignLocales(pages)` with no locales returns `locale: 'en'`, `rel === slug`; with `['en','es']` slug `es/guide/intro` becomes `{locale:'es', rel:'guide/intro'}`; `content/en/...` slug `en/x` throws; `['en','fr']` with no `fr` pages throws naming `fr`; `navFor` for `es` yields hrefs `/es/` and `/es/guide/intro/` and does not contain a group labelled "Es"; `navFor` order uses es-only `order`; `counterpart` finds across locales and ignores `order`/`title`; `switcherLinks` for an es-only page links `en` to `/` and for a translated page links to the English page; `alternates` is `[]` for an untranslated page and includes `x-default` for a translated one; `missingTranslations` lists an English page with no Spanish file; `rootRedirect(nav, '/es/')` returns null when the nav leads with `/es/` and a path otherwise (and the one-argument form is unchanged).

### Task 4: Wiring, chrome strings and layout

**Files:**
- Create: `src/site/lib/strings.js`, `src/site/components/LangSwitch.astro`, `test/strings.test.js`
- Modify: `src/cli/site.js`, `src/cli/build.js`, `src/site/layouts/Docs.astro`, `src/site/pages/[...slug].astro`, `src/site/components/RootRedirect.astro`, `src/site/components/Toc.astro`, `src/site/components/SearchDialog.jsx`, `src/site/lib/search-mount.jsx`, `src/site/lib/code-blocks.js` (and its call site), `src/site/pages/404.astro`

**Interfaces:**
- Consumes: everything from Task 2; `config.locales` from Task 3.
- Produces:
  - `strings.js`: `STRINGS: {en: Record<string,string>, es: Record<string,string>}` and `t(locale: string): Record<string,string>`. `t` merges the English dictionary under the match for the exact code, then for its base (`pt-br` looks up `pt-br` then `pt`); unknown locales return English. The `en` values must equal today's literals exactly.
  - `loadSite(root)` additionally returns `navs: Record<string, NavNode[]>`, `locales: string[]`, `localeRedirects: {slug: string, to: string}[]` (non-default locales without a home page, `to` already prefixed) and `missing` (from `missingTranslations`). `nav` and `redirect` keep meaning the default locale's. `pages` are `LocPage`s.
  - Virtual module `virtual:beacon` exports `navs`, `locales`, `localeRedirects` in addition to its current exports, and each page carries `locale` and `rel`. `nav` export is replaced by `navs`.
  - `build(root)` prints one `console.warn` line per non-default locale listing its missing translations; return value unchanged.
  - Layout: `<html lang>` is the page's locale (default `locales[0]` for the 404 page); the sidebar uses `navs[locale]`; the brand link goes to `homeHref(locale, locales)`; `LangSwitch.astro` (props `{links}` from `switcherLinks`) renders next to the theme toggle only when `locales.length > 1`; `<link rel="alternate" hreflang href={config.site + href}>` tags come from `alternates`; every chrome string comes from `t(locale)`; `[...slug].astro` adds one redirect route per `localeRedirects` entry (`params.slug` = the locale code).
